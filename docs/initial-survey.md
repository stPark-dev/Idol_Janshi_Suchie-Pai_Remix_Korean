### 2.1 스프라이트 묶음 형식 (확인)

`u32 헤더 크기 (= 8 + 8×개수)`, `u16 개수`, `u16 개수(같은 값)`, 항목마다 `u16 폭/8`, `u16 높이`, `u32 텍스처 오프셋(헤더 끝 기준)`. 텍스처는 4bpp 또는 8bpp, 헤더 없이 이어 붙임. VDP1 VRAM에서 꺼낸 텍스처가 묶음 안에서 바이트 단위로 나온다(메뉴·대국·규칙 화면에서 확인).

### 2.2 CX 컨테이너 (확인)

`u32 헤더 크기`, `u16 개수`, `u16 개수`, `u32 오프셋[개수]`(헤더 끝 기준). 항목은 세 가지:

- **비압축 묶음**: 2.1 형식 그대로 (`SELECT.CX` 15개).
- **압축 항목**: `u16 방식`, `u16 풀린 크기`, 스트림.
  - 방식 `0x0400` = 16비트 워드 RLE: 제어 워드 n(부호 있음) < 0 → 다음 −n 워드 그대로, n ≥ 0 → 다음 워드를 n+2번 반복.
  - 방식 `0x0000` = 바이트 RLE: 같은 규칙을 바이트 단위로.
  - 근거: `MJCG.CX` 항목 0을 풀면 62,040바이트(헤더 값과 같음)이고, 첫 텍스처가 대국 화면 VDP1 VRAM `0x7FC40`과 같다. 압축 항목 271개가 모두 헤더 크기대로 풀린다(형식 오류 0). 게임 해제 코드는 아직 찾지 않았다 → 재압축 결과는 게임 화면으로 확인해야 함.
  - 풀린 결과는 스프라이트 묶음(2.1) 또는 단일 그림 `[u8 폭/8][u8 높이]` + 8bpp/4bpp 픽셀.
- 풀리지 않은 항목: `TITL_CG.CX` #56(방식 `0x0C00`), `SELECT.CX` #13·#14(`0x0A40…`, 묶음 아님) — **미확인**.

### 3.6 대표 PoC: 압축 묶음 안 이름 칸 교체 (통과, 2026-10-16)

- 변경: `GAMEDRV/MJCG.CX` 항목 0(워드 RLE)을 풀어 「シホ」 이름 칸(72×16 8bpp, 묶음 오프셋 `0x7570`)을 「시호」(나눔스퀘어라운드 ExtraBold 13px, 색 번호 바깥선 `0x69`/안 `0x58`, 판 `0x54`)로 바꾸고, 우리 인코더로 다시 압축. CX 오프셋 표를 다시 계산하고, 파일을 원래 섹터(388개) 안에 제자리로 쓰고, ISO 디렉터리(`GAMEDRV`, LBA 24)의 크기 필드를 새 크기로 고침. 바꾼 섹터는 Mode 1 EDC/ECC를 다시 계산(원본 섹터 108개로 계산기 확인).
- 크기: 항목 0 39,672 → 39,422바이트, 파일 793,620 → 793,370바이트.
- 결과: Mednafen으로 PoC 디스크를 부팅해 1스테이지 대국에 들어가자 이름 칸에 「시호」가 원래 색으로 나옴(`work/evidence/poc-name-siho.png`). 글자 왼쪽에 점 하나가 남은 것은 PoC 스크립트가 원래 글자를 덜 지운 탓(「シ」가 지운 범위 왼쪽까지 걸침).
- 보여 주는 것: 게임 해제기가 우리 워드 RLE 스트림을 받아들이고, CX 오프셋 표 재계산과 ISO 크기 변경(작아지는 쪽)이 문제없음. 파일 시스템 경로로 읽으며 크기 표를 따로 두지 않는 것으로 보임.
- 보여 주지 않는 것: 파일이 원래 섹터 수보다 커질 때(옮기기), 바이트 RLE 항목, `TITL_CG.CX` 단일 그림, 비압축 BNN·`SELECT.CX` 제자리 교체(2편과 같은 방식이라 위험은 낮지만 이 게임에서는 아직 확인 안 함).

### 3.8 오프닝 큰 글자 (통과, 2026-10-16)

- 장면(원본 확인): `TITL_CG.CX` #5~#10 「アイドル雀士」가 하늘 위를 오른쪽에서 왼쪽으로 흐르고, 그 사이 검은 화면에 #11~#16 「ス·ー·チ·ー·パ·イ」가 한 글자씩 번쩍인다. 이어서 로고 장면.
- 노란 글자 칸(4bpp, 바깥 0)의 색 번호 구조: 테두리 13, 왼쪽 위 경사면 14·1·2·3, 몸통 4, 오른쪽 아래 그림자 9·7·5. 그림 글자 칸은 바깥 15, 안쪽이 캐릭터 그림(테두리 없음). 그림의 원본 전체 이미지는 디스크에서 찾지 못함(다른 그림 항목에 같은 조각 없음).

- 칸 배정: 아·이·돌·작·사 + 6번째 칸(士) 비움 / 스·(ー 원본 유지)·치·(ー 원본 유지)·파·이. 「ー」를 남긴 것은 오프닝 음성의 「스ー치ー파이」 박자에 맞추기 위함(Claude 결정, 소유자가 제작을 맡김 — 소유자 확인 필요).

### 3.9 SELECT.CX 그림 글자 (메뉴·캐릭터 선택·사운드 테스트·규칙, 2026-10-20)

- 범위: `SELECT.CX`의 비압축 묶음 5개(#0 메뉴, #1 캐릭터 선택, #10 규칙 표, #11 사운드 테스트, #15 안내 문구)에서 글자 항목 44개. 번역 `translation/select.json`, 배치 `assets/select/layout.json`. 영어(곡 제목, MAI 등 이름, GAME START, No.)는 그대로.
- 메뉴 버튼은 글자 하나가 패 한 장(24×39 8bpp)인 그림 24장. 원본의 빈 패(#20·#28)를 바탕으로 글자를 그린다. **#20·#28은 그 자체가 줄 안의 한 칸이기도 하다(확인)** — 처음 빌드는 #20에 「테」를 그린 뒤 셋째 줄이 바뀐 #20을 바탕으로 삼아 글자가 겹쳤다. 빈 패는 항상 원본에서 가져오도록 고침(회귀 테스트 있음).
- 패 배치(왼쪽 정렬, 남는 패는 빈 패): 캐릭터_선택__ / 사운드_테스트_ / 마작대회_규칙_ (원본도 둘째·셋째 줄 5번째가 빈 패).
- 글자 스타일은 원본 색 번호를 그대로 쓴다: 테두리 여러 겹(rings), 줄마다 바뀌는 그러데이션(사운드 테스트 제목), 굵은 몸통 안 흰 중심선(캐릭터 선택 안내 문구, inner). 규칙 표는 칸마다 항목 이름(0x01)과 값(0x02)을 나눠 그리고, 원본의 점선(…)은 뺐다. 글꼴: 나눔스퀘어라운드 ExtraBold, 규칙 표 칸은 나눔바른고딕 Bold 10~11px.
- 화면 확인(한글판): 메뉴, 캐릭터 선택, 사운드 테스트, 규칙 화면(`work/evidence/ko-menu.png`, `ko-charsel.png`, `ko-sound-rules.png`).
- 팔레트 메모: VDP1 스프라이트 색 = CRAM[(colr 뱅크 | 픽셀) + 0x100] (`CRAOFB`). 캐릭터 선택 글자는 colr 0x0080(64색), 규칙 표는 0x1A40.

### 3.10 상대 소개 카드·대전 이름 칸 (KAIWADIR/ROUND.BNN, PANELDIR/ROUND2.BNN, 2026-10-20)

- 카드 16장(112×32, 바탕 투명): 이름 한 줄(채움 0xAB·테두리 0x33)과 나이(0x65)·별자리(0xA7)·혈액형(0x64) 세 칸. 통째로 지우고 다시 그림. 긴 별자리(물고기자리)는 칸에 맞을 때까지 글자를 줄임(fit).
- 이름 칸 9개(112×26): 알약 판 위에 글자가 판 밖으로 삐져나오게 그려져 있고 글자 없는 판이 없다. 판 직선 구간의 글자 없는 세로줄 하나를 글자 영역 전체에 복사해 빈 판을 만든다(column). 판 색·글자 색은 칸마다 다르고 테두리(0x7E·0x92·0xA8)만 같다. 처음엔 기준 줄이 판의 둥근 끝(x=4)으로 잡혀 테두리가 한 줄 밀렸음 → 직선 구간 조건으로 고르고 회귀 테스트 추가.
- `PANELDIR/ROUND2.BNN`의 이름 칸 9개는 ROUND.BNN 17~39번과 바이트까지 같다(확인). 번역 표에서는 `ko_from`으로 같은 문구를 가리킨다.
