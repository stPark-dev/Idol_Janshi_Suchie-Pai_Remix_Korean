# 음성 자막

대사 음성에 한국어 자막을 붙이는 작업(v1.1)의 기록. 전례: 『스치파이 II』 한글판 v1.1 음성 자막(`../suchie-pai2/docs/voice-subtitles.md`) — 구조를 따르되 주소·형식은 이 게임에서 다시 확인한다.

## 1. 범위 (사람 결정, 프로젝트 소유자 2026-10-20)

- 자막 작업 시작 지시. 범위는 2편과 같은 기준을 기본으로 한다: 장면 음성(대국 전 대화, 벌칙·소개 장면 등)은 넣고, 대국 중 짧은 호출(리치·퐁 등)과 메뉴 안내 음성은 뺀다. 세부 목록은 음성 분류 뒤 다시 확인.
- 음성 분량(초기 조사 3.5): `KAIWADIR/OP*/` 91개 약 54분(대국 전 대화), `PANELDIR/` 333개 약 32분, `GAMEDRV/` 300개 약 9분(대국 중 호출), 루트 57개 약 7분.

## 2. 기술 조사 (2026-10-20, 정적 분석 + 세이브 스테이트)

실행 파일 `A`는 `0x06010000`에 올라가며 끝은 `0x060BB8D9`. 디스어셈블: binutils `sh4-linux-gnu-objdump -b binary -m sh2 -EB --adjust-vma=0x06010000`.

| 역할 | 주소 | 근거 |
|---|---|---|
| 파일 읽기 `load(name, dest)` | `0x0601A6A4` (리터럴 26곳) | GFS 이름→ID 뒤 GFS 읽기를 10번까지 재시도, 실패하면 BIOS 재시작(`*0x0600026C`) |
| 폴더 이동 `chdir(name)` | `0x0601A71A` (23곳) | 이름→ID → `0x060ADCDC`(디렉터리 읽기, 버퍼 `0x06097A00`) → `0x060ADD7A` |
| 음성 재생 `play(name)` | `0x0603BBBC` (14곳) | 재생 중이면 멈춤, GFS 열기, PCM 스트림 핸들(버퍼 사운드 RAM `0x25A7C000` = `0x7C000`), 시작, 상태가 2가 될 때까지 대기. 재생 중 표시 `0x06096C60` |
| 음성 재생(대기 후) | `0x0603BD4C` (31곳) | 같은 일을 몇 프레임 기다린 뒤 |
| 음성 정지 | `0x0603BCFA` | |
| GFS | 이름→ID `0x060ADDCC`, 열기 `0x060ADE7C`, 읽기 `0x060AE16E` | |
| PCM | 핸들 만들기 `0x060AF17C`, 시작 `0x060AF7A6`, 상태 `0x060AFA08` | 문자열 「PCM system is not initialized.」 |
| 프레임 훅 자리 | V-블랭크 시작 처리기 `0x0604D214`(BIOS `SYS_SETSINT` 벡터 0x40으로 등록)가 끝에 `0x060ABE48`(SCL 프레임 처리, 2편 `0x0608C9E4`와 같은 코드)로 넘어감 — 리터럴 `0x0604D2C0` 한 곳 | |
| VDP2 레지스터 사본 | 0x00~0xDF: `0x060B9DE4`, 0xE0~: `0x060BACE0` | 세이브 스테이트의 실제 레지스터 값과 RAM 대조 |

- **대화 음성 이름이 상대마다 같다**: `KAIWADIR/OPSIHO/MAI.AIF`, `KAIWADIR/OPRUMI/MAI.AIF` … 이름만으로 자막을 고를 수 없어 폴더 이동도 가로채 현재 폴더를 기억해야 한다(2편과 다른 점).
- **대화 장면 화면**: BGON 0x0003(NBG0·NBG1), CHCTLA 0x3232(둘 다 32768색 비트맵), NBG2·NBG3 꺼짐 — 2편 대화 장면과 같은 조건. 2편처럼 비트맵의 화면 밖 부분에 글자를 두고 NBG3 셀 면으로 그리는 방식이 맞을 것으로 본다(확인 필요).
- **빈 메모리**: 후보 구간 `0x060BB8DA`~`0x060FEC00`을 표시 값 0xA5로 채운 뒤 장면을 지나며 덮어써진 곳을 쟀다(libretro Beetle Saturn, `work/lr/memprobe.py`·`memprobe_win.py`).
  - 지난 장면: 데모·타이틀·메뉴·캐릭터 선택, 대국 전 대화(시호·사유리), 대국·유국·화료 결과, 패널 매치(카드 뒤집기·그림 공개), 스테이지 클리어, 탈의 장면(사유리), 컨티뉴.
  - 쓰인 곳: `0x060D0000`~`0x060D2BFF`(대국), `0x060FEAE0`~`0x060FEBFF`(스택 근처). **`0x060D2C00`~`0x060FEAE0`(179,936바이트)와 `0x060BB8DA`~`0x060D0000`(83,750바이트)은 한 번도 쓰이지 않았다.**
  - 못 지난 장면: 3스테이지 이후 상대의 대화·탈의, 우승(WINNER)·엔딩(DDGOOD·GOODEND). 2편처럼 특정 장면이 넘쳐 쓸 수 있으므로 자막 데이터는 합계로 확인하고, 매 프레임 도는 코드는 측정상 가장 안전한 곳에 둔다.
- **승리 도구** (`work/lr/win.py`, 조사용): 손패 `0x060996CA`(u16×13, 0~8 만·9~17 통·18~26 삭·27~33 자패) + 뽑은 패 `+0x1A`(없으면 0xFFFF), 우리 점수 `0x0609B1B0`(u16, 100점 단위), 상대 점수 `0x0609B26C`(u32). 판마다 한 번, 자기 차례에 버릴 패를 기다리는 동안 손패를 [일기통관 + 단기 + 자패 3장]으로 바꾸면 대기패를 뽑을 때 게임이 스스로 쯔모한다. 화료하면 손패 값에 0x200이 붙는다.
  - 다른 모양(커쯔 위주, 양면 대기, 구련보등)은 화료로 치지 않거나, 대기패를 뽑는 순간 손패 분석(`0x06035E84`, 결과 표 `0x0609AA48`)이 넘쳐 `0x0609AA45`~`0x060B25A9`를 덮어쓰고 CPU 예외 루프(BIOS `0x06000956`)에 빠진다. 같은 모양·시점이어도 가끔 멈추므로 50단계마다 체크포인트를 두고 멈추면 되돌린다. 3스테이지까지 가는 데 수만 단계가 걸려 엔딩까지는 아직 못 갔다.
- **연결 코드 자리(안)**: 파일 읽기 함수 본문(`0x0601A6A4`~`0x0601A6EB`, 72바이트, 리터럴 `0x0601A700`~`0x0601A70B`)을 "자막 코드가 있으면 그리로, 없으면 원래처럼 읽기"로 바꾸고, 재시도 포함 원래 읽기 동작은 자막 코드 안에 둔다. 리터럴 `0x0601A6F0`~`0x0601A6FC`는 바로 위 함수(`0x0601A674`, GFS 초기화)가 쓰므로 건드리지 않는다.

## 3. 구조 (2편 엔진을 옮김, 2026-10-20)

- **실행 파일 `A`** (같은 크기로 교체): 아무도 부르지 않는 SGL 함수 자리(`0x060A7840`~`0x060A78F6`, 리터럴·bsr·함수 표 어디에도 주소가 없음)에 연결 코드를 두고, 파일 읽기 `0x0601A6A4`를 가리키는 리터럴 26곳이 모두 연결 코드를 가리킨다. 연결 코드는 `SUB.BIN`이 RAM에 있으면(`BASE+0x10` = "KHSU") `BASE`로 가고, 없으면 현재 폴더에서 `SUB.BIN`을 찾을 수 있을 때만 원래 읽기 함수로 `BASE`에 읽고 캐시를 비운 뒤 다시 본다. 못 찾으면 원래 함수로 간다(없는 파일을 읽으면 10번 재시도 뒤 BIOS 재시작이므로 먼저 확인).
- **`SUB.BIN`** = 코드(≤ 0x2000, `tools/subtitle/`) + 색인. 코드의 `BASE+0x24`에 빌드가 `SUB.BIN`·`SUBDAT.BIN`의 FAD와 크기를 써 넣는다. 첫 호출 때 훅을 건다: 폴더 이동 `0x0601A71A`(리터럴 23곳), 음성 재생 `0x0603BBBC`(14곳)·`0x0603BD4C`(31곳), 수직 귀선 처리기의 SGL 프레임 처리 점프(`0x0604D2C0`). 훅이 걸렸는지는 플래그가 아니라 리터럴로 본다(리셋하면 실행 파일만 다시 읽히고 RAM의 SUB.BIN 변수는 남는다).
- **파일은 디스크 위치(FAD)로 안다**: 같은 음성 이름(`MAI.AIF` 등)이 루트·`KAIWADIR/OP*`·`PANELDIR/DDGOOD`·`WINNER`에 다 있다. 재생 훅은 이름을 GFS 이름→번호로 바꾼 뒤 현재 폴더 표(`0x06097A0C`, 24바이트 항목: FAD, 크기, 4바이트, 이름[12]; 0번 항목이 폴더 자신)에서 FAD를 읽는다. 그룹은 폴더 하나의 음성 묶음이고, 게임이 그 폴더로 들어가거나 거기서 파일을 읽을 때(어차피 CD를 쓰는 때) 읽는다.
- **아무 폴더에서나 우리 파일 읽기**: GFS는 현재 폴더 표로만 파일을 읽으므로, 읽는 동안 `..` 항목(1번, 게임이 열지 않음)을 우리 파일의 FAD·크기로 바꿨다가 되돌린다.
- **`SUBDAT.BIN`**: 그룹마다 LZSS(`tools/remix/lzss.py`, 2편에서 가져온 형식)로 압축해 이어 붙인다. 색인에 그룹마다 폴더 FAD·바이트 위치·압축/원래 크기.
- **디스크**: 두 파일은 트랙 1 마지막 파일(`GOODEND/MATAAIMA.AIF`, LBA 147218까지) 뒤 빈 섹터 300개(LBA 147218~147517)에 쓴다. 루트 디렉터리(4섹터)는 이름 순으로 다시 짠다. 다른 파일의 위치·크기는 그대로(통합 시험이 모든 파일을 대조).
- **메모리** (측정한 빈 구간 `0x060D2C00`~`0x060FEAE0` 안): `0x060EF000` 그룹 데이터(≤ 0xA000) / `0x060F9000` 코드(≤ 0x2000) / `0x060FB000` 색인(≤ 0x1000, 코드와 함께 읽음) / `0x060FC000` 셀 버퍼 / `0x060FD400` VRAM 사용 표. 색인·그룹은 합계로 확인하고 깨지면 다시 읽는다.

### 3.1 2편과 다른 점 (시험 중 찾음)

- **컴파일러**: Debian 12의 `sh4-linux-gnu-gcc` 12.2는 `index_ok()`의 `idx_bytes && …`에서 T비트 검사(`tst`)를 빼먹고 `bt.s`로 분기한다(이전 값의 T로 분기 → 그룹을 영영 안 읽음). `-O1`·`-fno-delayed-branch`로도 그대로. gcc 11.4(Ubuntu 22.04 패키지)는 올바르다 → `tools/subtitle/build.sh`는 gcc 11로 빌드한다(작업용 도구: `work/tools/shtc11`, 저장소에 넣지 않음). 커밋하는 `assets/subtitle/SUB.BIN`은 gcc 11.4 + binutils 2.38 산출물.
- **VDP2 레지스터 사본 업로드 시점**: 이 게임의 SGL은 수직 귀선 훅이 끝난 뒤 RAM 사본(`0x060B9DE4`)의 0x00~0xDF를 칩에 다시 올린다(0xE0 이후는 올리지 않음). 그래서 우리가 바꾸는 0x00~0xDF 필드(접근 패턴, BGON, CHCTLB, PNCN3, PLSZ, MPOFN, MPABN3/MPCDN3, SCXIN3/SCYIN3, 창 위치, WCTLB)는 사본에도 넣고, 배치 판단에 쓰는 값(`shadow()`)은 게임 원래 값을 돌려주며, 줄이 끝나면 게임이 그동안 다시 쓰지 않았을 때만 원래 값으로 되돌린다. 2편은 SCYIN3만 이렇게 했다.
- **팔레트 행**: 대화 장면은 컬러 RAM 앞쪽 행을 거의 다 쓴다(2편이 보던 행 4~7·12~15 모두 사용 중). NBG3가 닿는 모든 행(컬러 RAM 오프셋 × 256 + 팔레트 × 16, 모드 1이면 128행)을 끝에서부터 찾는다. 2편 코드의 CRMD 판정이 RAMCTL 비트 8~9를 보던 것도 바로잡음(비트 12~13).

### 3.2 확인 (libretro Beetle Saturn, 2026-10-20)

- 시험 디스크(시호 대화 `KAIWADIR/OPSIHO/MAI.AIF`에 시험 문장 5줄, 받아쓰기 시각)를 처음부터 켜서 메뉴 → 캐릭터 선택 → 대화: 대화 화면 아래 검은 띠(y 200~231)에 다섯 줄이 차례로 대사에 맞춰 나옴. 음성 키온은 재생 호출 14프레임 뒤.
- 남은 확인: 그 밖의 장면(패널 매치·탈의, 우승·엔딩, 캐릭터 소개)의 배치, 연결 코드 자리(`0x060A7840`)가 정말 불리지 않는지 전 장면 실행, 실기.
